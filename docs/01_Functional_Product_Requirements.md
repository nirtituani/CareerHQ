# 1. Overview

This document defines the functional requirements, product behavior, workflows, and constraints for CareerHQ.

It serves as the primary product specification before architecture and implementation begin.

All subsequent design documents—including System Design, AI Architecture, Database Design, and API Design—derive their requirements from this specification.

---

# 2. Product Goals

CareerHQ aims to:

- Centralize the complete job search workflow into a single intelligent platform.
- Maintain one Professional Profile as the user's single source of truth.
- Generate tailored Resume Versions for each job opportunity.
- Reduce repetitive work through AI-assisted workflows.
- Keep users fully in control of every AI-generated change.
- Build long-term career intelligence based on accumulated application history.

---

# 3. Success Metrics

The success of CareerHQ will be evaluated through measurable outcomes.

## User Success

- Reduce application preparation time.
- Improve resume relevance for target positions.
- Reduce repetitive manual work.
- Increase user confidence before submission.

## Product Success

- High AI recommendation acceptance rate.
- Improved Resume Match Score.
- Accurate identification of recurring skill gaps.
- High workflow completion rate.
- Reliable and explainable AI recommendations.

---

# 4. Assumptions

The following assumptions define the initial product scope.

- CareerHQ is designed for individual users.
- Every user owns exactly one Professional Profile.
- Professional Profile is the system's single source of truth.
- Resume tailoring always begins from a selected Resume Profile.
- Submitted resumes are immutable.
- AI recommendations require explicit user approval.
- Internet connectivity is available for AI-powered capabilities.

# 5. Core Domain Concepts

## Professional Profile

The Professional Profile represents the user's complete professional knowledge.

It contains structured information including:

- Experience
- Skills
- Projects
- Education
- Certifications
- Languages

The Professional Profile serves as the system's single source of truth.

---

## Imported Resume

An Imported Resume is an existing CV file the user uploads.

It is **parsed into structured Professional Profile content** and then discarded as a primary
artifact. The uploaded file is never the source of truth — the structured data extracted from it
is. Parsing is AI-assisted and always reviewed by the user before the content is accepted.

This is the primary way a Professional Profile is populated in Version 1. Building a profile from
scratch through a guided editor is future work.

---

## Resume Profile

A Resume Profile represents a career-oriented presentation of the Professional Profile.

It is referred to in the product interface as a **Master Resume** — for example "Backend Master"
or "AI Backend Master". The two terms describe the same entity: `Resume Profile` is the domain
name, "Master Resume" is what the user sees.

Each Resume Profile defines:

- Default Professional Title
- Preferred Summary
- Preferred Skills
- Preferred Projects
- Preferred Experience Highlights
- Default Resume Template

Examples:

- Backend Engineer
- AI Backend Engineer

Resume Profiles reference information from the Professional Profile without duplicating it.

---

## Resume Version

A Resume Version is generated by tailoring the selected Resume Profile to a specific Job Description.

Resume Versions may be reviewed before export.

---

## Submitted Resume

A Submitted Resume is an immutable snapshot of an exported Resume Version.

Submitted resumes cannot be modified.

---

## Application

Represents a single job application.

Stores:

- Company
- Job Description
- Submitted Resume
- Current Status
- Notes
- Interview Feedback

---

## Company

Represents a researched company.

Stores AI-generated research together with optional user notes.

# 6. Functional Requirements

---

## Professional Profile

### Purpose

Maintain the user's professional knowledge.

### User Story

**US-001**

As a job seeker, I want to maintain a single Professional Profile so that I never need to duplicate my professional information.

### Functional Requirements

**FR-001**

The system shall maintain exactly one Professional Profile per user.

**FR-002**

The Professional Profile shall support structured information including:

- Experience
- Skills
- Projects
- Education
- Certifications
- Languages

**FR-003**

Users shall be able to update their Professional Profile over time.

### Acceptance Criteria

- Users can update professional information.
- Updates are immediately available for future Resume Versions.

---

## Resume Import

### Purpose

Populate the Professional Profile from an existing CV, so a user reaches value without manual
data entry.

### User Story

**US-007**

As a job seeker, I want to upload my existing CV and have CareerHQ understand it, so that I do
not have to retype my career history before the platform is useful to me.

### Functional Requirements

**FR-024**

The system shall accept an uploaded resume file in PDF or DOCX format.

**FR-025**

The system shall extract structured content from the uploaded file — contact information,
professional titles, summary, work experience with individual bullets, skills, projects,
education, certifications, and languages.

**FR-026**

The system shall present the extracted content to the user for review, correction, and approval
before any of it becomes part of the Professional Profile.

**FR-027**

Extracted content shall be marked with its source and confidence so that user-verified facts
remain distinguishable from unverified extraction.

**FR-028**

The system shall create an initial Resume Profile from the approved import, so the user has a
Master Resume to tailor from immediately.

**FR-029**

The uploaded file shall be retained for reference but shall not be the source of truth for any
downstream capability.

### Acceptance Criteria

- A PDF or DOCX resume is accepted and parsed.
- Extracted content is displayed for review before it is stored.
- The user can correct any extracted field.
- Approving the import produces a populated Professional Profile and one Resume Profile.
- No downstream feature reads the original file.

---

## Resume Profiles

### Purpose

Support multiple career-focused resume configurations.

### User Story

**US-002**

As a job seeker, I want multiple Resume Profiles so that I can target different career paths without maintaining duplicate resumes.

### Functional Requirements

**FR-004**

A Professional Profile shall support multiple Resume Profiles.

**FR-005**

Resume Profiles shall reference Professional Profile information.

**FR-006**

Resume Profiles shall define presentation preferences without duplicating data.

### Acceptance Criteria

- Users can create Resume Profiles.
- Users can rename Resume Profiles.
- Users can archive Resume Profiles.

---

## Resume Tailoring

### Purpose

Generate a tailored Resume Version by combining a Professional Profile, a selected Resume Profile, and a Job Description.

### User Story

**US-003**

As a job seeker, I want CareerHQ to tailor my resume for a specific job so that I can maximize my relevance while preserving the accuracy of my professional information.

### Functional Requirements

**FR-007**

The system shall analyze the provided Job Description.

**FR-008**

The system shall retrieve relevant information from the selected Professional Profile and Resume Profile.

**FR-009**

The system shall generate a tailored Resume Version.

**FR-010**

The system shall calculate a Resume Match Score.

**FR-011**

The system shall generate AI recommendations explaining proposed improvements.

**FR-012**

The system shall generate a visual diff between the original Resume Profile and the tailored Resume Version.

**FR-013**

Users shall explicitly approve AI-generated changes before creating the Resume Version.

**FR-014**

Approved Resume Versions shall be exportable as PDF.

**FR-015**

Exported resumes linked to Applications shall become immutable Submitted Resumes.

**FR-030**

Every Resume Version shall record which Resume Profile it was created from and the state of that
profile at creation time. After creation the Version is an independent document — **lineage is
recorded, not inherited**. Updating a Resume Profile shall never alter any Version created from it.

**FR-031**

Resume Versions shall progress through the lifecycle `Draft → Ready → Exported → Submitted`.
Marking a Version as Submitted shall lock it permanently: it cannot be edited, and it can be
viewed, re-downloaded, or duplicated into a new Version, but never modified in place.

**FR-032**

Content inclusion shall be controlled at the individual item level — each experience bullet,
skill, and project may be included in or excluded from a given Resume Version without being
removed from the Professional Profile.

**FR-033**

When a Resume Profile changes after Versions have been created from it, the system may inform the
user that a newer Master is available for future tailoring. It shall never modify an existing
Version, and shall never modify a Submitted Resume under any circumstance.

### Acceptance Criteria

- Job Description is analyzed successfully.
- Relevant professional information is selected.
- Resume Match Score is displayed.
- AI recommendations include explanations.
- Visual diff is generated.
- Users approve changes before export.
- Resume Version is created successfully.

# 7. AI Requirements

**AI-001**

Analyze the provided Job Description.

**AI-002**

Extract required skills, technologies, and qualifications.

**AI-003**

Retrieve relevant professional information.

**AI-004**

Generate a tailored Resume Version.

**AI-005**

Calculate a Resume Match Score.

**AI-006**

Generate explainable recommendations.

**AI-007**

Generate a visual diff.

**AI-008**

Never fabricate professional experience or qualifications.

**AI-009**

Require explicit user approval before applying AI-generated changes.

**AI-010**

Ensure every AI-generated recommendation is reversible.

**AI-011**

Extract structured professional content from an uploaded resume file, returning typed data rather
than prose, with a confidence indication per extracted item.

**AI-012**

Critique its own proposed output before presenting it to the user. A Reviewer step shall verify
that every claim in a tailored resume is grounded in existing Professional Profile content, detect
overstated or unsupported phrasing, and check coverage against the Job Description requirements.

**AI-013**

Produce a Confidence Score for each tailored Resume Version and request revision from the
generating agent when that score falls below an acceptable threshold.

**AI-014**

Never present output that failed its own Reviewer check without surfacing what failed.

# 10. MVP Scope

Included in Version 1:

- Resume Import and structured parsing
- Professional Profile (populated by import, correctable by the user)
- Resume Profiles / Master Resumes
- Resume Tailoring with self-critique
- Resume Match Analysis

# 12. Future Roadmap

Future releases may include:

**Resume Builder (from scratch)** — a guided, section-by-section editor for composing a resume
without importing one, with a live preview beside the form. The target experience is the Teal /
Gloat resume builder: per-item inclusion checkboxes, drag-to-reorder sections, and a completeness
indicator. Version 1 populates the profile by import instead, because the underlying data model is
identical and the builder is purely an additional interface over it.

**Resume Designer** — user-controlled presentation: template library, typography (font family,
sizes, weights, transformations), spacing controls, header/date/location alignment, skills layout,
bullet and separator glyphs, borders, and section renaming. Version 1 ships a single well-designed
ATS-safe template. The `ResumeLayout` value object already carries these fields, so this is an
interface addition rather than a schema change.

Also planned:

- Interview Coach
- Application Workflow Agent — proactive follow-up prompts, stale-application detection, and
  deadline awareness
- Learning Planner
- Cover Letter Generation
- LinkedIn Integration
- Calendar Integration
- Email Integration
- Multi-user Collaboration
